# Change: add-config-module

## Why

Приложению нужен централизованный модуль конфигурации для загрузки и валидации настроек из YAML файла. Текущая архитектура предполагает глобальный ConfigModule на верхнем уровне модульной иерархии, но он ещё не реализован. Без валидации конфигурации существует риск ошибок в runtime при неверных или отсутствующих параметрах.

## What Changes

- Создать ConfigModule с глобальной областью видимости
- Реализовать ConfigService для загрузки конфигурации из YAML файла
- Путь к конфигурационному файлу определяется через переменную окружения `CONFIG`, по умолчанию `config/local.yml`
- Определить Zod схему для валидации всех секций конфигурации
- Поддержка переопределения и добавления новых параметров через переменные окружения (формат: `OPC_PORT`, `MQTT_BROKER`, и т.д.)
- Генерировать TypeScript типы из Zod схемы
- Реализовать graceful crash при отсутствии файла или ошибке валидации
- Предоставить единственный метод для доступа ко всей конфигурации в типизированном виде (без методов `get(key)`)
- Конфигурация читается только один раз при старте сервиса
- Добавить unit тесты для ConfigService

**BREAKING**: None - это новая функциональность

## Impact

- Affected specs: Новая спецификация `config-management`
- Affected code: `src/config/config.module.ts`, `src/config/config.service.ts`, `src/config/config.schema.ts`
- Integration: Все другие модули будут зависеть от ConfigModule для получения конфигурации
